## Decisions
- PDF generation is strictly client-side (no backend route).
- Ecosystem access is delegated to the GestionaTools Hub SSO; this app does not use Supabase Auth for login.
- The old local catalog is imported from `old/seed.js`; old IDs are preserved in `legacy_id`.
- Internal primary keys remain UUIDs generated by Supabase/Postgres.
- Multilingual fields from the old app are stored as JSONB (`*_i18n`), while the current UI still renders Spanish labels.
- RLS is enabled, but read/write policies are intentionally pending until the SSO-to-Supabase identity model is finalized.
- Normalized schema with `informeobjetivos_v_items_export` for UI/PDF reads.

## Recent updates
- Client-side PDF export aligned to selected items with per-item deadline and observations.

- Hub SSO route, signed local session cookie, middleware guard, local logout, and CRUD for items implemented.
